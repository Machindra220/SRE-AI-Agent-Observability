Deployment phases
Phase 22-A Infrastructure Bootstrap infra-up-complete.sh ▶
1. EKS Clustereksctl creates cluster + VPC + subnets
2. Node Groupsapp_nodes (×3 t3.small) + agent_nodes (×1, tainted)
3. IAM RolesOIDC provider + service account IRSA bindings
4. aws-load-balancer-controllerHelm install — provisions ALBs for services
5. Namespacessre-ai-agent, sre-ai-agent-llm, monitoring, chaos
6. SecretsECR pull secret, GEMINI_API_KEY, Grafana token
✓ kubectl get nodes → 4 Ready INSTALL_DATADOG=false INSTALL_LITMUSCHAOS=false
Phase 22-B pgvector + Runbook Seeding deploy-pgvector.sh ▶
1. pgvector StatefulSetPostgreSQL + pgvector extension in sre-ai-agent-llm
2. PVC10Gi EBS volume for vector index + runbook data
3. Seed runbooksEmbed SRE runbook chunks → store in pgvector
4. VerifySELECT COUNT(*) from runbook_chunks → N rows
✓ pgvector ready namespace: sre-ai-agent-llm port: 5432
Phase 22-C FastAPI App Deploy deploy-app.sh ▶
1. Build imagedocker build → push to ECR
2. Deployment3 replicas of FastAPI app in sre-ai-agent
3. Service (LoadBalancer)AWS ELB → /health, /metrics endpoints
4. HorizontalPodAutoscalermin=2, max=5 replicas on CPU 70%
✓ GET /health → 200 namespace: sre-ai-agent replicas: 3
Phase 22-D LangGraph Agent Deploy deploy-agent.sh ▶
1. Agent imageBuild LangGraph 4-node pipeline → push ECR
2. Deployment1 replica on agent_nodes (toleration: workload=ai-agent)
3. Service (LoadBalancer)Exposes /agent/triage for Grafana webhook
4. GEMINI_API_KEY secretMounted as env var for diagnoser node
✓ POST /agent/triage → RCA returned namespace: sre-ai-agent-llm node: agent_nodes
Phase 22-E Prometheus + Grafana (local) infra-up-complete.sh ▶
1. kube-prometheus-stackHelm install — Prometheus + Grafana + AlertManager
2. ServiceMonitorsScrape sre-ai-agent /metrics every 15s
3. PrometheusRulesHigh error rate, pod restarts, p99 latency alerts
4. local Grafana dashboardImport sre-ai-agent-dashboard.json
✓ Prometheus scraping namespace: monitoring port-forward: 3000
Phase 23 Grafana Cloud + Alerting Webhook configure-grafana-cloud.sh ▶
1. remote_write configPrometheus → Grafana Cloud Mimir (scarletcanary2090)
2. Alert rules (Cloud)Pod Restart Rate High, High Error Rate, p99 Latency
3. Contact pointWebhook → http://<AGENT_LB>/agent/triage
4. Notification policyRoutes sre-ai-agent alerts to webhook contact point
5. GRAFANA_CLOUD_API_KEYAdded to .env — used by Prometheus + Promtail
✓ Metrics visible in Grafana Cloud stack: scarletcanary2090 region: ap-south-1
Phase 24-A chaoskube (pod killer) deploy-chaoskube.sh ▶
1. chaos namespaceIsolated from app — chaoskube runs here
2. RBACClusterRole: list+delete pods in sre-ai-agent only
3. Helm install chaoskube v0.29.0interval=2m, minimumAge=30s, ~50MB RAM
4. Verify kill logskubectl logs -n chaos deployment/chaoskube
✓ Pod killed every 2 min target: sre-ai-agent DRY_RUN=false
Phase 24-B Promtail → Grafana Cloud Loki deploy-loki-promtail.sh ▶
1. .env credentialsLOKI_USER_ID=1800xxx + GRAFANA_CLOUD_API_KEY
2. promtail-loki-secretkubectl create secret in monitoring namespace
3. Helm install Promtail DaemonSetvalues.yaml + --set credentials; 1 pod per node
4. Scrapes 4 namespacessre-ai-agent, sre-ai-agent-llm, chaos, monitoring
5. Verify in Grafana CloudExplore → Loki → {namespace="sre-ai-agent"}
✓ Logs in Grafana Cloud Loki url: logs-prod-028.grafana.net tolerations: Exists
Phase 24-C Grafana Cloud Chaos Dashboard grafana-chaos-dashboard.json ▶
1. Import JSONGrafana Cloud → Dashboards → Import
2. Bind datasourcesDS_PROMETHEUS → grafanacloud-...-prom · DS_LOKI → ...-logs
3. 5 dashboard rowsChaos Status · Impact · LangGraph RCA · Events · AI Quality
4. Update webhook URLAlerting → Contact point → set real AGENT_LB hostname
✓ Live chaos + RCA visible refresh: 30s 8 panels
