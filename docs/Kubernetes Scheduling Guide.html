Part 1

The Problem — Why Pod Placement Matters

When you deploy a pod in Kubernetes, the scheduler decides which node it runs on. By default, it picks any available node. This sounds fine — until you have a cluster with different kinds of nodes doing different jobs.

Imagine your cluster has three nodes:

Without scheduling control: random pod placement — expensive nodes wasted, busy nodes overloaded.

This is the exact problem that Taints & Tolerations, Node Affinity, and Pod Affinity/Anti-Affinity solve. Think of them as three different tools — each with a different job.

Mental model before you read on

Taints = a "No Entry" sign on the door of a node.
Tolerations = a special pass that lets your pod ignore that sign.
Affinity = a pod's own preferences about where it wants to live.

Part 2

Taints & Tolerations — The Bouncer Model

A taint is set on a node. It says: "I don't want just any pod here."

A toleration is set on a pod. It says: "I'm okay with that node's restriction, let me in."

Think of a nightclub. The bouncer (taint) stands at the door. Only guests with the right wristband (toleration) get in.

The Bouncer model — only pods with the matching toleration get past the taint.

Setting a taint on a node

kubectl
kubectl taint nodes gpu-node-1 gpu=true:NoSchedule

The taint format is always key=value:Effect. The three effects are:

EffectWhat it doesUse when…
NoSchedule New pods without toleration won't be placed here. Existing pods stay. You want to reserve a node going forward
PreferNoSchedule Scheduler tries to avoid this node but may use it if nothing else is available. Soft preference — not critical
NoExecute New pods blocked AND existing pods without toleration are evicted. Node is unhealthy or needs full evacuation

Adding a toleration to your pod

pod-spec.yaml
spec:
  tolerations:
    - key: "gpu"
      operator: "Equal"
      value: "true"
      effect: "NoSchedule"

There's also a wildcard form — tolerate every taint on the node:

tolerate ALL taints (used by DaemonSets)
tolerations:
  - operator: Exists   # no key or value — matches everything
⚠ Common mistake

Tolerations only allow a pod to land on a tainted node — they don't guarantee it. A pod with a toleration can still end up on any untainted node. To guarantee placement, you also need affinity (covered next).

Real-world example — your SRE project

In the SRE-AI-Agent project, agent-nodes (the node that runs LangGraph) has this taint:

eksctl — applied during infra-up
--node-taints "workload=ai-agent:NoSchedule"

This keeps pgvector, Prometheus, and other pods off that node, reserving its resources entirely for the LangGraph RCA agent. Only the LangGraph pod has a toleration for workload=ai-agent, so only it gets in.

The one exception is Promtail (the log shipper DaemonSet). It needs to run on every node including agent-nodes. So it uses the wildcard:

deploy-loki-promtail.sh
tolerations:
  - operator: Exists   # DaemonSet — runs on ALL nodes regardless of taints
Part 3

Node Affinity — Attraction

Node Affinity is a rule on a pod that says: "I want to run on a node that has this label." Unlike taints (which push pods away from nodes), affinity pulls a pod toward certain nodes.

Node Affinity pulls the pod toward nodes with the matching label.

Hard vs Soft rules

TypeKeywordMeaning
Hard requiredDuringSchedulingIgnoredDuringExecution Must match — pod stays Pending forever if no node matches
Soft preferredDuringSchedulingIgnoredDuringExecution Try to match — but schedule on any node if needed
langgraph-deployment.yaml — Hard rule
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: role
                operator: In
                values: ["agent"]   # must land on a node with role=agent
✓ Best practice: use both

In your SRE project, the agent-node has a taint (keeps others out) AND the LangGraph pod has affinity (pulls it specifically here). Taint alone leaves the pod floating; affinity alone lets the pod land anywhere the taint isn't. You need both for guaranteed exclusive placement.

Part 4

Pod Affinity & Anti-Affinity — Social Rules

So far, pods have been expressing opinions about nodes. Now pods can express opinions about other pods.

Pod Affinity: "Schedule me on the same node as pod X."
Pod Anti-Affinity: "Schedule me on a different node from pod X."

Left: Pod Affinity groups pods together (low latency). Right: Anti-Affinity spreads replicas across nodes (high availability).

Pod Affinity — co-locate for low latency

fastapi-deployment.yaml — "sit near Redis"
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: redis-cache       # find nodes that already have Redis
          topologyKey: kubernetes.io/hostname   # "same node"

Pod Anti-Affinity — spread for high availability

fastapi-deployment.yaml — "never share a node with my own replicas"
spec:
  affinity:
    podAntiAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: sre-ai-agent     # don't co-locate with pods that share my label
          topologyKey: kubernetes.io/hostname   # "different node"
What is topologyKey?

topologyKey defines the boundary. kubernetes.io/hostname means "per node". You can also use topology.kubernetes.io/zone to spread across availability zones, or topology.kubernetes.io/region for regions. The key must match a label that exists on the nodes.

Part 5

Using All Three Together

In a real production cluster, you combine all three mechanisms. Here is how the SRE-AI-Agent project uses them:

Your full SRE cluster — three mechanisms working together: taint (repels), toleration (allows), affinity (attracts).

The complete LangGraph deployment spec

langgraph-deployment.yaml — all three mechanisms
apiVersion: apps/v1
kind: Deployment
metadata:
  name: langgraph-agent
  namespace: sre-ai-agent-llm
spec:
  replicas: 1
  template:
    spec:
      # 1. TOLERATION — "I can handle the taint on agent-nodes"
      tolerations:
        - key: "workload"
          operator: "Equal"
          value: "ai-agent"
          effect: "NoSchedule"

      # 2. NODE AFFINITY — "I want to land on role=agent specifically"
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
              - matchExpressions:
                  - key: role
                    operator: In
                    values: ["agent"]

      containers:
        - name: langgraph
          image: 123456789.dkr.ecr.ap-south-1.amazonaws.com/langgraph-agent:latest
          resources:
            requests:
              cpu: "500m"
              memory: "512Mi"
            limits:
              cpu: "1000m"
              memory: "1Gi"
Part 6

Quick Reference

Mechanism Set on Direction Use for
Taint Node Node repels pods Reserve a node; keep noisy neighbours out
Toleration Pod Pod bypasses a taint Allow a specific pod onto a reserved node
Node Affinity Pod Pod attracted to node label Guarantee pod lands on specific hardware
Pod Affinity Pod Pod co-located with another pod Low-latency: app + cache on same node
Pod Anti-Affinity Pod Pod separated from another pod High availability: spread replicas across nodes

🔒 Taint + Toleration

The access control pair. Taint locks the node; toleration is the key. Always used together. Neither is useful without the other.

🧲 Affinity (Node)

Tells a pod where to go. Hard rules cause Pending forever on failure; soft rules fall back gracefully.

👥 Pod Affinity

Group latency-sensitive workloads. FastAPI and its Redis cache on the same node cuts network hops to zero.

↔ Pod Anti-Affinity

Force replicas apart. If one node dies, the other replicas survive. The most common HA pattern in Kubernetes.

The golden rule

Taint = the node sets the rules.
Toleration = the pod says "I accept your rules."
Affinity = the pod says "And I specifically want to go there."

For guaranteed exclusive placement: you need all three. Taint keeps others out. Toleration lets you in. Affinity makes sure you actually go there instead of somewhere else that has no taint.
